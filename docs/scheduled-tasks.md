# 统一计划任务

## 注册与事实来源

`scheduled_tasks` 保存计划、版本、锁及下一次运行时间，`scheduled_task_runs` 保存执行记录。业务服务在 API 依赖装配中注册 `TaskHandler`、校验参数，并在 Engine 启动前完成幂等默认任务创建、兼容迁移和遗留扫描恢复；修改计划后通知 Engine。新增周期任务接入这一套 Registry、Service、Engine、Runner，不启动模块私有调度器。入口见 [`internal/scheduledtask`](../internal/scheduledtask/) 和[架构与进程边界](architecture.md)。

- 站点备份旧计划和访问分析旧设置仅供启动幂等迁移；保留旧定时备份 API 的兼容读写，底层仍操作统一任务。访问分析设置保存同步相应任务。
- ACME 续签、Nginx 站点日志切割和 GeoIP 更新复用系统任务；以任务表为事实来源，设置页同步任务，不恢复旧 ACME 或 Nginx 日志切割 YAML 调度字段，也不覆盖已有系统任务配置。
- Agent 只执行一次性 Nginx 日志切割 RPC，使用自身配置的日志目录，完成重命名、`reopen` 和数量与年龄双条件清理。API／Agent 各自的运行日志轮转由进程内 writer 负责，与站点切割独立；计划任务日志沿用现有任务日志目录。

## 调度、队列与抢锁

- 统一编译日／周／月、固定间隔和 cron；cron 使用分钟级表达式，时区独立校验，不在表达式中内嵌时区。只支持 `skip` 并发策略，错过执行可 `run_once` 或 `skip`，不能以重启为由无限补跑。重新启用时补算 `next_run_at`，一次执行完成后按持久化结果安排下一次运行，避免重复重排。
- 定时引擎使用每任务单节点的索引最小堆、合并 dirty ID 唤醒和周期性 DB 权威对账。派发前重读并检查任务启用、锁、版本和 `next_run_at`；队列满把任务留在堆中等待重试。手动 `RunNow` 进入独立有界队列，停用任务不接单，满载返回 `BUSY`。固定 worker 和共享 Runner 并发槽覆盖两条路径，不能按到期项启动无界 goroutine。
- Runner 在 SQLite 中原子抢占任务及创建 run。执行记录带 `task_version`、`runner_id`；完成时以任务 ID、版本、`last_run_id` 和 `locked_by` 校验归属。旧执行可以结算自己的记录，不能覆盖并发修改后的任务状态或释放其他执行的锁。过期锁与匹配的 `running` run 在同一事务恢复，run 标记为 `abandoned`。

## 准入、退出与清理

- 调度服务使用根 context，单次执行有超时；取消或 panic 必须收尾，必要时用独立有界 context 结算执行记录，再释放锁或交由过期恢复。更新试运行可以先准备调度状态，确认前不启动正常派发。
- 业务准入与 Runner 准入都要保留：备份创建、恢复和定时任务共享备份槽；ACME 长任务有自身容量；手动和计划访问分析均防止同站并行。拒绝准入不创建孤立任务状态，结束释放槽位。访问分析事务、SSE 和资源细节见[安全与资源约束](security.md)。
- API 维护循环按终态 `finished_at`（旧异常记录回退 `created_at`）或每任务数量清理历史，永不删除 `running`；登录审计也由此循环按自身策略维护。退出取消维护并等待，不另起竞争清理器。
