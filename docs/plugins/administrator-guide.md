# 插件中心使用教程

nxPanel 的“发现”页只展示由 nxPanel 官方接口提供的插件。官方仓库地址和初始 TUF 信任根随正式发行版内置，管理员不能在运行时替换为第三方仓库。

## 官方插件

进入“插件中心 → 发现”，刷新目录后即可查看官方插件。安装前请检查版本、兼容状态、权限和所需 Provider；商业插件会标注“需授权”。官方插件的目录元数据与 `.nxp` 包均经过 TUF 的 root、timestamp、snapshot、targets 链验证，包的长度和 SHA-256 必须与目标元数据一致。

无法连接官方服务时，面板只会使用尚未过期的可信缓存。缓存过期后不能新增安装或更新，但已安装插件会继续运行。不要通过修改缓存文件或系统时间绕过过期检查。

插件更新如果增加或删除权限，必须重新确认。卸载前先停用插件；WAF 插件还要求先关闭所有站点的 WAF。

## 开发者模式与本地安装

仅在开发或内部测试时进入“插件中心 → 开发者”开启开发者模式。开启操作会保存为面板全局设置，并要求明确确认以下风险：

- 本地 `.nxp` 没有官方 TUF 签名；
- manifest 中的发布者名称只是自我声明，不能证明身份；
- 插件仍受权限、配额、WASM 沙箱和固定 Agent Provider 限制，但获批能力可能读取或修改面板数据。

开发者模式只提供本地文件选择，不支持粘贴 URL，也不支持配置第三方仓库。安装分为两步：

1. 选择一个 `.nxp`，由服务端检查路径、摘要、文件数量、压缩和展开大小、manifest 与 WASM；
2. 复核文件名、包 SHA-256、插件 ID、声明发布者、版本、权限、网络域名和 Provider，然后再次确认安装。

检查结果以一次性随机 token 表示，15 分钟后过期，API 服务重启后也会失效。包在确认阶段会再次校验；token 不能重复使用。

开发者插件不能使用保留的 `org.nxpanel.*` ID，也不能覆盖官方目录已有的 ID。若官方目录后来声明了相同 ID，现有开发者插件可以继续运行，但会标记来源冲突，并禁止更新或重新启用；移除它之后才能安装官方版本。

## 关闭开发者模式

关闭开发者模式不会自动停用或卸载现有开发者插件，正在运行的插件会继续运行。关闭后：

- 允许停用和卸载开发者插件；
- 禁止上传、检查和安装新的本地包；
- 禁止本地更新；
- 已停用的开发者插件不能重新启用。

插件中心会持续提示仍在运行的开发者插件数量。若要彻底回到纯官方状态，请逐个停用并卸载它们。

## 插件授权

无需提前在设置页填写 License Key。商业插件的授权只在实际下载时触发：

1. 像免费插件一样检查权限并点击安装；
2. 插件服务返回“需要授权”后，面板展示用户验证码和官方登录地址；
3. 在新页面登录插件服务账户，核对验证码并批准；
4. 面板确认账户权益后，自动继续原下载和安装。

nxPanel 不接触插件服务账户密码，只加密保存短期访问令牌和可撤销的刷新令牌。一个面板可以保存多个账户，不同插件可以绑定不同账户。同一插件只使用当前明确绑定的账户；无权益、权益过期或实例数量已满时不会静默尝试其他账户，必须由管理员手动选择后重新校验。

撤销账户不会停用已经安装的插件，但会解除相关绑定，并阻止依赖该账户的后续下载和更新。令牌密钥丢失或刷新令牌失效时，需要通过新的设备验证码重新登录。

## 安全边界

- 插件没有任意 shell、root 文件系统或自带原生 `.so` 加载能力；
- 官方与开发者插件使用相同的权限 broker；来源可信度不同，不代表运行权限不同；
- 开发者插件可以申请系统已注册的受控能力，包括固定 WAF Provider，但必须在安装时完整展示和批准；
- 插件 UI 在无同源权限的 `sandbox="allow-scripts"` iframe 中运行；
- 所有 Provider 调用和生命周期变更都进入操作审计。
