# Nginx 模块商店使用指南

适用范围：使用新版 NxPanel 的宿主机和 Docker 部署。不需要克隆模块仓库、下载 `.so`、运行安装脚本或部署构建服务。负责运维模块服务的维护者请看[部署指南](nginx-module-store-deployment.md)。

## 安装模块

1. 确认已运行 NxPanel 管理的 Nginx/OpenResty，并能在 **Nginx 管理 → 状态管理** 看到活跃 worker。
2. 打开 **Nginx 管理 → 模块管理**（`/nginx?tab=modules`），点击 **刷新在线目录**。找到模块，点击 **安装**，选择正式 Release。默认选择最新正式版，也可以按需加载更早的版本。
3. 等待预检。如果存在匹配的签名成品，点击 **确认安装**；如果提示「需构建」，按[按需构建](#按需构建)操作。
4. 等待安装任务成功，模块显示「已启用」。构建成功不等于安装成功；Agent 会重新验签，在本机试载并检查配置，通过后才平滑重载。

> 正式模块的安装、卸载脚本由 Agent 验签后以 root 执行。Docker 部署中，运行库和模块装在 NxPanel 容器内，不装到宿主机。安装不会自动升级 Nginx；模块可能从现有系统源安装所需的运行库。

以 **GeoIP2** 为例，安装成功后还需在 **面板设置 → GeoIP** 安装 MMDB，再在站点访问限制中配置地域规则。单独安装 GeoIP2 不会下载数据库或自动启用规则。参见[访问限制和地域规则](access-policy.md#geoip2-升级与回滚)。

## 按需构建

构建发生在官方服务的专用构建机上，不在你的服务器上。服务按所选模块 Release 和实际运行时匹配成品；相同构建输入可复用缓存。**下载已有成品不需要令牌，发起新构建需要授权。**

| 安装窗口状态 | 操作 |
| --- | --- |
| 需构建 | 有权限时点击 **申请构建**；没有此按钮时，请向服务运营方申请令牌，或等同环境的成品发布后重新检查 |
| 构建排队中 / 构建中 | 等待面板自动刷新，可关闭窗口；之后用同一 Release 重新打开查看，不必重复提交 |
| 可确认安装 | 点 **确认安装**；离开窗口后重新进入也要通过预检 |
| 构建失败 / 不支持构建 | 查看原因；若使用自行编译的 Nginx、上游不再提供所需包，或服务未配置该运行时，改选有匹配成品的正式 Release，或联系维护方 |

构建期间若升级了 Nginx，旧成品不一定适用；用当前运行时重新预检。即使版本范围命中，Nginx 也可能因 ABI 不兼容拒绝加载，不能通过放宽范围强装。

## 配置服务地址和授权

发行版已内置服务地址、且只安装现成成品时，**不需要额外配置**。如果运行时留空，构建时也没有内置地址，则没有默认域名，也不会访问 GitHub。此时请向运营方索取实际 HTTPS 源站。需要配置源站或构建令牌时，把下列设置交给 **Agent**，不要填到浏览器或面板登录信息中：

```dotenv
NXPANEL_MODULE_STORE_URL=https://modules.example.com
NXPANEL_MODULE_BUILD_TOKEN=替换为运营方发放的令牌
```

地址只能是受信任的 HTTPS 源站；只需要设置的项才填写。覆盖服务地址不会替换 Agent 内置的根公钥。源必须提供由同一根签发的授权清单；仅改地址不能绕过签名校验。Agent 不直连 GitHub；各版本的 Release 清单由服务镜像提供。

- **宿主机（systemd）**：把变量保存到仅 root 可读的 `/etc/nxpanel-module-store.env`（`0600`）。执行 `sudo systemctl edit nxpanel-agent`，在 `[Service]` 下添加 `EnvironmentFile=/etc/nxpanel-module-store.env`，再执行 `sudo systemctl restart nxpanel-agent`。
- **Docker Compose**：在 NxPanel 部署目录的 `.env` 中设置变量；确认使用支持这些变量的 Compose 模板。改环境变量需要重建容器，不是 `docker restart`。若已有在线安装的模块，先按下一节的步骤处理，再用原 profile 执行 `docker compose --profile nginx up -d` 或 `docker compose --profile openresty up -d`。

## 卸载、升级和排查

1. 卸载前先停用并同步依赖模块的站点规则，移除手写配置中使用该模块的指令。GeoIP2 的 MMDB 和面板规则数据可以保留。
2. 在 **模块管理** 点击 **卸载**。面板只卸载它管理的动态模块；手动加载或静态编译的模块不在此处卸载。凭据和授权公钥仍有效时，可以离线卸载。
3. **升级 Nginx/OpenResty 或重建 NxPanel 容器前，先卸载在线安装的模块。** 模块文件和卸载凭据默认不随容器重建保留，持久化的 Nginx 配置却可能仍引用旧模块。新运行时启动后重新预检、安装模块，再恢复依赖规则。只更换模块版本时，也要先卸载，再安装目标 Release。

| 现象 | 建议 |
| --- | --- |
| 在线目录不可用 / 只显示缓存 | 点击 **刷新在线目录**，检查 Agent 到 HTTPS 模块服务的网络和证书。缓存只能查看，不能新装；面板不会回退 GitHub。 |
| 找得到模块，但没有匹配的成品 | 确认所选 Release 与当前系统、架构、运行时相符；有源码构建选项时按需申请。不要手动替换 `.so` 或关闭签名检查。 |
| 无法核验 Nginx 实例或挂载路径 | 在状态管理确认 Agent 管理的是正确实例、有活跃 worker，且两者看到同一份主配置和模块目录。不必为此关闭 systemd 安全加固。 |
| 卸载提示仍有依赖或凭据异常 | 检查访问规则和手写指令；凭据损坏或签名公钥被撤销时请联系维护方，不要手动删除托管目录。 |
| 提示「需人工检查」 | 先保留操作记录、Nginx 日志、配置、`/var/lib/nxpanel-nginx-modules/script-task.json` 和记录中列出的任务目录；由维护人员核对配置与 worker 状态后处理，不要反复强行重试。 |
