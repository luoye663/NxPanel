# 统一访问规则编排

在“网站管理 → 详情 → 访问限制”中统一管理 IP、地域、路径、后缀、Referer 和密码验证规则。新建站点默认使用空规则，未命中时放行；导入站点和升级前已有站点保留原配置。

## 匹配与保存

规则从上到下匹配。禁用规则不参与判断；未命中继续下一条；首条命中后执行放行、拒绝或密码验证。密码错误或缺失返回 401，通过后放行，不再判断后续规则。列表底部决定全部未命中时的行为。

每条规则支持“全部满足”或“任一满足”，条件可取反。同一个条件内的多个值表示任一值匹配。IP 支持 IPv4、IPv6 和 CIDR；地域使用 GeoLite2 Country，`ZZ` 表示未知地域；路径支持精确匹配或前缀匹配；后缀和 Referer 域名忽略大小写。Referer 中 `none` 表示空值，`blocked` 表示没有有效 HTTP/HTTPS 协议的值，`server_names` 使用站点域名。

拖动、上下移动、编辑、删除和启停只改变草稿，点击“保存并应用”后才更新 Nginx。每站点最多 256 条规则，每条最多 16 个条件，条件值合计最多 65,536 个。自定义响应正文最多 64 KiB UTF-8，状态码支持 400–599；444 直接关闭连接。

“测试请求”展示各规则的判断结果和最终命中项。地域由输入 IP 查询，不接受独立的国家覆盖。预览不验证密码，也不模拟上游应用、WAF 或整个 Nginx 请求流程。

## 旧站点切换

旧模式页面可以生成迁移草稿，读取草稿不会修改配置。旧白名单的“其他 IP 拒绝”会变成显式规则；旧地域默认拒绝也会显示为可排序的规则。旧 `location` 优先级与统一规则顺序不能保证完全等价，迁移提示会列出差异。不能直接转换的条件必须编辑或移除后才能保存。

首次保存成功后进入统一模式。已经进入迁移应用但结果未确认时，旧规则写接口也会拒绝修改，以免覆盖可能已经生效的新配置。

反代密码验证作为关联规则参与排序。关联路径跟随反代配置，反代停用时关联规则暂停参与判断，但保留用户自己的启用开关。需要独立编辑路径或组合方式时，先解除关联。删除反代会同时移除关联规则。

ACME 没有隐藏的放行优先级。如需放行验证路径，可以添加可见的路径规则并调整顺序。自定义 Nginx 配置中会绕过或覆盖规则判断的指令，需要在应用前处理冲突。

## 应用失败、备份和接口

配置通过单个 Agent 文件事务应用，执行 `nginx -t`，按站点启用状态 reload。面板分别记录待应用版本与已确认版本；超时或连接中断不视为“肯定未应用”。“同步”用于重试待应用版本。反代和关联规则一起修改失败时，必须一起同步，不能仅保存规则。

账户和 GeoIP 更新只刷新已确认策略，不会自动发布未完成的编辑。配置／完整备份包含策略快照和认证依赖；恢复前检查账户冲突，不覆盖其他站点或全局账户的密码。文件恢复成功但数据库元数据提交失败时会明确报错，不报告全部成功。

站点 API（位于现有认证及 CSRF 保护之下）：

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/sites/{site_id}/access-policy` | 获取已保存策略或只读迁移草稿 |
| PUT | `/sites/{site_id}/access-policy` | 提交完整策略，携带读取时的 `version`；版本冲突返回 409 |
| POST | `/sites/{site_id}/access-policy/preview` | 提交 `{policy, request: {ip, path, referer}}` 预览草稿 |
| POST | `/sites/{site_id}/access-policy/sync` | 同步未完成的应用 |

失败响应的 `desired_saved` 和 `saved_version` 用于区分“草稿已持久化但未确认应用”与“保存前失败”；编辑器不会用旧服务端配置覆盖尚未保存的本地草稿。
